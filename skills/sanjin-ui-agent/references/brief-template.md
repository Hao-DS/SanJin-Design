# 原型需求最小模板（S1 折叠路径）

本模板用于**折叠档**：单页、不新增路由、不引入新数据实体、无权限与高风险动作，且用户未要求设计需求文档。满足这些条件时，S1 折叠为下面的 10 行假设回显，不产出 `design/design-spec.md`，直接进 S2；S4 用 `handoff.light.md`。

页面 ≤ 2 且无高风险、但不满足折叠条件时，走轻量档：复制 `design-spec.light.md`，不要读本文件。

其余走完整 S1：复制 `design-spec.template.md`；任务流推不出或 G1 不过时再读 `prd-to-design-spec.md`。档位与门禁见 `pipeline.md`。

## Agent 决策规则

1. 已有工程中能识别组件库 → 沿用现有栈，不重复询问。
2. 未识别到栈 → 询问一次；用户未回复、说“默认”或不关心 → 使用 Semi Design（React）。
3. 已有截图、Figma 或页面 → 视为视觉与布局证据；交互未知处标为待确认，并实现低风险合理默认值。
4. 未给数据口径 / 接口 → 使用明确标注为 mock 的数据，结构应能替换为真实接口。
5. 未给权限规则 → 默认实现可演示的无权限状态，不伪造真实鉴权。

## 最小输入

仅在以下信息确实缺失且阻止实现时提问：

```markdown
主任务：用户进入页面后最需要完成什么？
目标用户：谁使用？
页面范围：新建页面 / 改造现有页面 / 仅某个模块？
技术栈：沿用项目 / Semi（默认）/ Nubes / Ant / TDesign？
已有材料：截图、Figma、链接、旧页面、字段或接口？
风险动作：权限、导出、批量修改、发布、自动执行是否存在？
```

## 默认假设回显

开始实现前，用不超过 10 行回显：

```markdown
实现栈：Semi Design（默认）
主任务：审核并处理内容队列
范围：列表、筛选、详情抽屉、批量操作
数据：本地 mock；真实接口待接入
状态：loading、无结果、错误、无权限均可演示
待确认：审核后的真实状态流转与权限来源
```

## 原型完成定义

### 硬规则

- 至少一条主任务闭环：入口 → 输入/筛选 → 操作 → 进行中 → 成功或失败 → 结果落点。
- 每个高风险动作显示影响范围和确认。
- 所有状态包含文字，不只靠颜色。
- 组件 API 有当前技术栈证据，写入 `evidence.json`。

### 推荐规则

- 用 mock 数据覆盖长文本、空数据、错误和权限不足等边界。
- 明确本次未实现的真实接口、鉴权和异步任务。

折叠路径同样要过 G2–G4：闭环可用、视觉合格、`HANDOFF.md` 按 `handoff.light.md` 写全。省掉的只有 `design-spec.md`。
