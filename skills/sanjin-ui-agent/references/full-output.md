# 完整输出（反截断）

横切规则，S1–S4 全程适用，写代码时最关键。

截断不是能力问题也不是上下文丢失，是模型在长任务里默认采取的省力行为。所以治它的办法不是「请认真一点」，而是**先锁定交付数量，再逐项核对**，以及在真的写不完时用显式断点，而不是偷偷缩水。

## 禁止的输出模式（硬规则）

出现以下任何一种，视为未完成，不得交付。

**代码里**：`// ...`、`// 其余同理`、`// 剩余列略`、`// TODO`、`// 此处实现`、`/* ... */`、`// 参照上面`、`// 按需补充`，以及用裸 `...` 代替真实代码。

**文字里**：「其余页面同理」「篇幅所限」「剩下的结构一样」「以此类推」「需要的话我可以继续补充」「留作扩展」。

**结构性偷工**：

- design-spec 列了 6 个页面，只实现 3 个然后说明其余「结构相同」；
- 表格 design-spec 定义了 12 列，只写 5 列；
- 写了列表页但把详情抽屉留成空壳；
- 多个同类页面只认真做第一个，其余复制后不改内容；
- `evidence.json` 只记前几个组件，其余写「同上」；
- `HANDOFF.md` 的表格只填一行示例，其余留占位符。

最后两条在流水线里尤其常见，因为它们出现在交付末尾，正是省力压力最大的时刻。

## 执行流程

**1. 锁定数量。** 动手前把本轮要交付的东西数清并写下来：几个页面、每页几个模块、表格几列、几条主任务闭环、几个状态、几条 mock 记录。这个数字来自 design-spec，不是临场决定的。

**2. 逐项完成。** 不留半成品，不先铺骨架再说「稍后填充」。

**3. 交付前回数。** 对照第 1 步的清单逐个核对。少了就补完再输出，不要在交付说明里用「已实现主要页面」这类模糊表述掩盖。

## 写不完怎么办

不压缩、不跳到结论、不降低后半部分的质量。写到一个干净断点（一个文件结束、一个页面结束、一个模块结束），然后显式标注：

```text
[暂停 - 已完成 3 / 6：任务列表、任务详情、告警规则。
 待完成：规则编辑、执行历史、权限配置。
 回复「继续」从「规则编辑」接着写。]
```

继续时直接从断点往下，不重述已完成的部分。

## 多页面工程

并行生成多个页面时截断风险最高：前两页认真写，后面开始复制粘贴不改内容。

- 分发前在主上下文定好共享的布局壳、导航、token 用法和实体命名，让每个页面只需要专注自己的内容。
- 每个页面单独核对它在 design-spec 第 5 节里的模块清单，不要整体扫一眼就算过。
- 合并后做跨页一致性检查：同一实体的名称、状态词、操作位置、表格列顺序是否一致。**一致不等于雷同**——各页的内容必须按各自职责真实填写，复制出来的重复页面属于截断的一种。

## 与门禁的关系

G2 的「design-spec 里每个页面都存在且可达」、G4 的「无占位符残留」都会检出截断，但那时已经在返工了。本文件的作用是在写的过程中就不产生它。
