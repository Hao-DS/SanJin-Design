# 信息层级

**管什么**：用视觉表达已确认的任务信息——主次、关系、呈现形式和阅读顺序。

**何时读**：新建或重组页面；主次不清；视觉元素开始互相争抢注意力。

**不管**：空间与滚动读 `references/ui-judgment/layout.md`；界面状态读 `references/ui-judgment/states.md`；准确取值读 `references/DESIGN.md`；组件内部样式以选定栈证据为准。

## 先明确任务

### Don't

- 不把页面类型当成完整任务。「做一个数据看板」还要说明用户要查看、比较还是操作什么。
- 不照搬业务字段顺序、接口返回顺序或现有组件来安排页面。
- 产品内容未经确认时，不擅自新增、改写或删除。

### 设计原则

先从已确认的事实回答：**谁、在什么场景下、要对什么对象、完成什么任务。** 无法确认的标为待确认。

同类任务优先沿用产品现有的信息结构和交互模式；只有任务目标或约束不同，才重新设计。

再判断每条信息在任务中的作用：

| 作用 | 判断问题 |
| --- | --- |
| 任务 | 用户在处理什么对象，要完成什么动作 |
| 工作 | 完成任务必须查看、输入、选择或比较什么 |
| 支持 | 哪些说明、示例、限制、来源会影响理解与操作 |
| 元数据 | 哪些时间、创建者、标识符只用于补充 |
| 系统信息 | 哪些进度、错误、权限、同步状态会改变下一步 |

## 突出重点

### Do

- 优先级确认后，同级信息使用一致的视觉权重；主要动作与关键结果明显强于辅助信息。
- 必须同时决策、且后果对等的动作作为一组呈现。
- 眯眼看页面时，仍能看出当前任务的重点和主要操作。

### Don't

- 不在界面上显示「任务级、工作级、支持级」这类内部分类名。
- 不让辅助动作、装饰或低影响状态与主要操作争注意力。
- 没有产品依据时，不用字号、面积或颜色制造优先级。

### 设计原则

按信息对当前任务的作用判断权重：

| 层级 | 包含内容 | 本技能的典型载体 |
| --- | --- | --- |
| 任务级 | 页面目标、关键结果、主要动作 | 页面标题（`page-title`）、KPI 主数字（`kpi-value`）、唯一 primary 按钮 |
| 工作级 | 主体内容、输入、比较和选择 | 主表格 / 主图表、筛选条、表单（`body-md`） |
| 支持级 | 解释、范围、辅助动作、次要导航 | 筛选摘要、字段说明、default / link 按钮（`body-sm` 或 `ink-secondary`） |
| 元数据级 | 时间、ID、来源、不影响操作的状态 | 更新时间、创建人（`ink-tertiary`） |

首次使用、日常操作和失败恢复三种场景的重点可以不同。

**时间和状态不固定属于元数据**——是否阻塞任务、后果大小、恢复成本决定它的层级。任务已失败时，
失败原因是任务级信息，不是角落里的一行灰字。

## 表达内容关系

### Do

- 先用标题、顺序、邻近、对齐和留白表达关系；仍不清楚时再加背景或边框。
- 原因与结果、控件与它的反馈放在一起。错误与恢复动作也放在一起。
- 字段名、必填标记和影响填写的约束持续可见；placeholder 只放格式示例，不代替标签。
- 自检：去掉卡片背景、边框和图标后，靠标题、顺序和邻近关系仍能说明分组。

### Don't

- 不用多层卡片嵌套代替内容分组。每多一层 surface，就要能说出它为什么必须独立成区。
- 不靠增加容器、边框或底色来补救层级没想清楚的问题。
- 不把同一组信息拆到相距很远的两个区域。

### 设计原则

只有内容需要独立成区、或进入浮层时，才增加一层独立 surface（取值见 `references/DESIGN.md` 的 canvas / surface / elevated 三层）。
普通分组优先用标题、间距和分隔线表达。

## 选择呈现形式

### Do

- 按用户要对信息做什么来选形式：**看趋势**用图，**做比较和定位**用表，**看单值结论**用 KPI，**读因果**用文字。
- 一个图表只回答一个主要问题；需要回答第二个问题时，拆成第二个图或改用表。
- 数量级差异大、或维度超过表格可读范围时，先降维再呈现，不把完整报表塞进首屏。

### Don't

- 不因为「看起来更丰富」把表格换成图，也不因为「图不好做」把趋势塞进表格。
- 不用装饰性插画、进度墙、统计条填充空白区域。
- 不在同屏重复表达同一事实（KPI 已给出总量时，图上不再重复标注同一总量）。

### 设计原则

呈现形式服从任务，不服从视觉丰富度。首屏模块预算是硬规则，见 `references/DESIGN.md` 与 `references/visual-quality.md`。

## 安排阅读与操作顺序

### Do

- 按「决策摘要 → 解释 → 明细」组织纵向顺序，这是 B 端数据页的默认阅读路径。
- 让视觉顺序、DOM 顺序和键盘焦点顺序保持一致。
- 操作放在它作用的内容附近；影响全页的操作放页头，影响某区域的放该区域内。

### Don't

- 不用绝对定位或视觉重排造成「看到的顺序」与「Tab 的顺序」不一致。
- 不把主操作藏在需要滚动或 hover 才能发现的位置。
- 不在一屏内设置两个竞争的入口起点。

### 设计原则

阅读顺序先于组件摆放。先能用一句话说清「用户第一眼看哪、然后看哪、最后点哪」，再开始布局。
