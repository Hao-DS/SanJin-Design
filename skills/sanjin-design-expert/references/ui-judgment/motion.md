# 动效

**管什么**：判断界面要不要动效、动效表达什么信息、以及怎么降级。

**何时读**：设计操作反馈、展开收起、进入退出、运行过程、hover 预览或 reduced motion 时。

**不管**：状态内容与反馈载体读 `references/ui-judgment/states.md`；具体时长、曲线和组件内部动画以选定栈的组件契约为准。

B 端数据台的默认气质是克制（见 `references/DESIGN.md`）。本节的默认答案是**不加动效**，下面是少数应该加的情况。

## 判断动效是否必要

### 设计原则

动效必须至少表达一项真实信息：

- 操作已被接收；
- 因果关系或空间关系；
- 变化前后是**同一个对象**；
- 过程仍在进行；
- 刚出现、且需要用户处理的变化。

**删掉动效后不影响理解或操作的，就不要加。**

### Don't

- 不用动效掩盖加载慢、状态缺失、布局跳动或性能问题。
- 不为普通页面添加装饰性入场、过程动画或抖动。
- 不给首屏默认内容加入场动画。

## 先定义清楚再实现

选择动效前先回答：

- 哪次操作或界面变化触发它；
- 哪个元素从什么状态变到什么状态；
- 哪些内容必须保持稳定；
- 反向、取消或快速重复时停在哪里；
- reduced motion 下如何保留同一信息。

不要用动画名称代替状态定义。拖拽、滑杆这类连续输入不要强拆成几个离散状态。

## 控制频率与注意力

### Do

- 循环动画在完成、失败、暂停或离开可视区后必须停止。
- 高频操作——切换 Tab、选中列表行、键盘导航——直接更新内容，不播放过渡。
- 自动播放或循环的内容提供可见的暂停控件（随任务状态短暂出现并自动停止的除外）。

### Don't

- 不让高频切换的内容每次重新入场。
- 不做逐字、逐行、逐节点的机械延迟入场，也不让它阻塞操作。
- 普通展开和局部切换不做多段入场。
- 同一屏不让多个无关的循环动画争抢注意力。

### 设计原则

高频变化的反馈应当即时。只有**低频、且改变任务阶段或页面层级**的变化，才值得用更明显的位移。

## 进入、退出与切换

### Do

- 有明确方向的浮层或面板，沿进入路径退出；居中的 Dialog 保持居中。
- 展开时保持入口和原有内容位置稳定；关闭应立即响应，不分段、不延迟。
- 页面切换只让变化区域参与动效，共享导航和固定外框保持稳定。

### Don't

- 内容替换已经清楚表达结果时，不再叠加庆祝或抖动动画。
- 不让同一个对象从一侧进入、从另一侧退出。
- 没有明确空间方向时，不强加方向性位移——直接切换或轻量淡入淡出即可。
- **不缩放包含正文、表格或大量内容的容器**，`transform: scale` 会连同全部子元素一起缩放导致文字模糊。
- 普通菜单、Dialog 和内容切换不加回弹或过冲。
- 主题切换不要让颜色、边界、阴影逐元素依次播放。

## 按压与 hover 反馈

### Do

- 组件已提供按压反馈时直接沿用，不重复添加。
- 按压反馈在按下瞬间发生，**不等待请求结果**。
- hover 效果限定在精确指针设备：

```css
@media (hover: hover) and (pointer: fine) {
  .row:hover { background: var(--surface-subtle); }
}
```

- 位移类 hover 保持可交互区域不动，只移动内部视觉层。
- 键盘和触屏必须有等价的入口与反馈。

### Don't

- 不让 hover 承担唯一反馈。
- 按压反馈不能代替 loading、success、error——前者说明「操作已收到」，后者说明「结果是什么」。

## 连续输入与中断

- 拖拽、滑杆、可拖动面板在输入过程中持续跟随。
- 动画允许从当前状态反向播放，或立即跳到正确的终态。
- **中断后的结果必须符合当前状态**，而不是动画原计划的终点。
- 正在退出的内容不再接收操作。
- 动画不得阻塞其他可用控件。

## Reduced motion

尊重系统设置，但**不要连状态反馈一起删掉**：

```css
@media (prefers-reduced-motion: reduce) {
  .panel { transition: none; animation: none; }
}
```

- 移除大幅位移、缩放、视差和循环，直接显示终态。
- 停止循环后，静态图标、文字或进度信息仍必须可见。
- 终态已足够清楚时直接切换；仍需过渡时只保留 opacity 或 color。

## 实现与验证

### Do

- 优先用 `transform` 和 `opacity` 实现动画。
- 只声明需要过渡的**具体属性**：仅透明度变化用 `transition: opacity ...`；同时改变透明度和位移用 `transition: opacity ..., transform ...`。
- 实际触发 hover、focus、pressed、展开收起、loading 和空态等相关路径逐一检查。
- 覆盖快速重复、反向和中途取消，用慢放检查错位、跳变和闪现。

### Don't

- **业务页面不使用 `transition: all`**（会连带过渡布局属性，造成不可预期的抖动和性能问题）。
- 不长期为大量元素设置 `will-change`。
- 不在业务代码里重写组件库已有的时长、缓动或关键帧。
