# 布局与滚动

**管什么**：内容的位置、尺寸、对齐和滚动归属，以及容器、内容或输入方式变化后的重排。

**何时读**：新建或调整布局；出现密度、对齐、溢出、截断、响应式、多语言问题。

**不管**：信息主次读 `references/ui-judgment/hierarchy.md`；状态读 `references/ui-judgment/states.md`；间距与圆角的准确取值读 `references/DESIGN.md`；组件内部尺寸与焦点管理以选定栈证据为准。

## 确认布局环境和滚动归属

这是 B 端后台最容易出错、也最难事后补救的一层，动手前先定下来。

### Do

- 先确认内容位于整页、现有 Shell、面板、抽屉还是 Dialog，再判断主工作区、辅助区和横纵滚动的归属。
- **同一工作区、同一方向只设一个主滚动容器。**
- Flex 布局里：固定区域设 `flex-shrink: 0`；**纵向滚动的子项必须设 `min-height: 0`**；横向可收缩的子项必须设 `min-width: 0`。
  漏掉后两条时，子项会被内容撑开而不是产生滚动，表现为整页跟着滚或出现两条滚动条。
- 为可折叠、可拖拽调整的分区明确最小值、最大值、折叠入口和恢复规则；未确认的值标为待确认。
- 固定或 sticky 区域遮挡滚动内容时，为滚动容器预留等高的内边距，确保最后一项能完整滚入视口。
- 确需嵌套同向滚动时，明确边界：内层滚到头后仍能继续滚动外层。

以视口为根的桌面工作台外壳可用这个结构（嵌入已定高父级时把 `height: 100vh` 改成 `100%`）：

```css
.shell        { display: flex; height: 100vh; overflow: hidden; }
.shell > aside{ flex-shrink: 0; }
.shell__main  { display: flex; flex-direction: column; flex: 1; min-width: 0; }
.shell__head  { flex-shrink: 0; }
.shell__body  { flex: 1; min-height: 0; overflow: auto; }
```

### Don't

- 不默认套用外壳、仪表盘、卡片墙等版式；先确认任务需要它。
- 不用固定高度掩盖滚动边界没想清楚的问题。
- 不把 `100vh` 当作移动端可见高度的通用答案（地址栏会改变实际视口）。
- 不叠加边界不清的同向滚动。

### 设计原则

页面默认自然增长。**只有当父级高度确定、且用户需要在固定工作区内持续操作时，才建立内部滚动。**

## 选择布局方式

| 方式 | 适用关系 |
| --- | --- |
| 文档流 | 按阅读顺序自然展开 |
| Flex | 一维排列、控件组、主次两栏、剩余空间分配 |
| Grid | 行列关系同时重要，字段或卡片需要稳定对齐 |

### Do

- 只有一条主阅读或输入流时，用限宽单列并居中（内容区建议上限见 `references/DESIGN.md`）。
- 同类入口集合从单列起步，空间足够再增列；只有已确认的优先入口才跨列或放大面积。
- 主工作区优先获得空间，辅助区只保留完成职责所需的宽度。

### Don't

- 不因为仓库里已有某个模板或组件，就强行套单列、入口网格或双视图。
- 宽度按任务和内容分配，不默认等宽、不默认对半分。
- 屏幕变窄时不强行保留双栏；主任务内容优先，辅助内容下移、收起或改按需显示。
- 不用负 margin、`calc()` 或绝对定位绕过父级布局（内容确需重叠或组件自带定位行为时除外）。

### 设计原则

双视图（如卡片 / 表格切换）只有在两种视图分别支持真实的查看、比较或操作需求时才成立，且切换后要保留必要状态。
做不到就只留一种。

## 间距、圆角与对齐

取值一律用 `references/DESIGN.md` 的 4px 基线与 8 / 16 / 24 / 32 刻度。本节只讲怎么选档位。

### Do

按**关系紧密程度**选间距，不按重要性：

| 关系 | 起点 |
| --- | --- |
| 图标与文字、紧密标签 | 4px |
| 控件组内部、字段内部 | 8px |
| 同一内容分组内 | 8–16px |
| 相邻分组之间 | 24px |
| 页面级区域之间 | 24–32px |

- **组内间距必须小于组间间距**，同类关系用同一档位。
- 组件内部 padding 沿用组件契约，不在页面层覆盖。
- 紧密嵌套且四周 padding 一致时，外圆角 = 内圆角 + padding，算完从 `references/DESIGN.md` 现有档位里取最接近值。
- 按列比较时**文字左对齐、数字右对齐**。
- 连续变化、会造成宽度跳动的数值（计时、实时指标）使用 `font-variant-numeric: tabular-nums`。
- 位数、正负号或单位会变化时，按已确认的最长格式为数值容器预留空间。
- 勾选框、单选框的控件、标签及两者间的空白都应可点击。

### Don't

- 不另造一套 px 间距表，也不为套嵌套圆角公式写出非标准值。
- 不为整齐强行对齐无关内容，不靠增加嵌套容器修小错位。
- **不用更紧凑的密度代替信息层级。** 挤不下通常是信息没分主次，不是间距太大。
- 相邻控件的可交互区域不得重叠；装饰层不得拦截点击。

### 设计原则

间距表达关系，不表达重要性。浏览和比较大量数据可以更紧凑，首次引导和低频配置可以更舒展。密度由任务决定。

## 空间不足时如何重排

### Do

- 对每个会变化的区域明确：哪些内容保留，哪些换行、堆叠、滚动、折叠或移入次级入口。
- 重排后让视觉顺序、DOM 顺序和键盘焦点顺序仍然一致。
- 超宽屏限制正文、表单和逐项编辑区的行宽；不要让一行控件横跨整屏。
- 触控场景提升控件高度（见 `references/DESIGN.md` 响应式章节），并验证安全区与软键盘弹出后的可见区域。

### Don't

- 不只写「桌面 / 平板 / 手机」，也不用设备名代替具体的重排规则。
- 不用 CSS `order` 或 `grid-area` 单独改变视觉顺序而不改 DOM 顺序。
- 不把固定断点当成通用答案——文字增长和容器宽度可能比设备宽度更早触发问题。
- 不逐项压缩到不可用。先保留完成任务所需的内容和操作，再整组换行、堆叠、折叠或滚动。

### 设计原则

在内容开始拥挤、截断、失去比较关系，或让操作不可达时重排，而不是到某个固定像素值时重排。

## 工具栏与表格

### Do

- 搜索与筛选属于同一任务组时，工具栏变窄应**整组换行**，独立操作（新建、导出）保持可用且贴右。
- 表格与分页按工作区类型二选一：
  - **自然内容流**：表格与分页依次排列，分页右对齐，整页滚动。
  - **父级已定高**：表格容器 `flex: 1; min-height: 0; overflow: auto`，分页 `flex-shrink: 0` 常驻底部。
- 窄容器中优先保留列间比较，把横向滚动放在明确的容器上，并固定识别列。
- 只截断不影响当前任务、且另有全文入口的次要内容。

### Don't

- 不继续压缩已失去可用宽度的控件，也不为填满空间增加无关按钮。
- 不默认把窄屏表格改成卡片——先确认卡片仍能支持原来的比较任务。
- 身份标识、错误原因、完成任务必需的信息不能只剩省略号。

### 设计原则

列是否固定、表格是否内部滚动、内容是否截断，都由**比较任务**和**父级空间**决定，不由表格宽度单独决定。
列优先级与滚动策略是硬要求，见 `SKILL.md` 的 B 端数据页面规则。

## 多语言与长内容

### Do

- 标题、说明、按钮、标签允许在合理位置换行。
- URL、ID、代码、无空格长串要明确选择换行、滚动还是提供复制入口。
- 使用截断时，必须同时提供**不依赖 hover** 的全文入口（详情页、展开、复制）。
- 正文、ID、代码和日志保持可选中。
- 用产品中真实可能出现的中文、长英文、大数字、空值和本地化文案测试。

### Don't

- 不用固定高度假设文字永远单行。
- 不把 hover 当成查看全文或完成核心操作的唯一方式。
- 不在页面或根容器设置 `user-select: none`。

### 设计原则

内容变长是正常情况，不是异常。选择换行、滚动还是截断时，先保证内容仍可理解、可比较、可操作。

## 验证布局

### Do

- 从最窄目标宽度到超宽屏**连续缩放**检查，不只抽查几个设备宽度。
- 分别检查 0 条、1 条和大量数据下的高度与滚动表现。
- 用键盘、鼠标和触屏分别检查核心操作、点击区域和焦点顺序。
- 页面自管滚动容器时，确认键盘焦点所在元素始终可见、且不被固定区域遮挡。

### Don't

- 不以单张桌面截图或单一示例数据声称布局已适配。
- 未实际验证的项标为「未验证」，不写成已通过。
