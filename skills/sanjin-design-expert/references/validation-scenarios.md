# 技能验证场景

以下场景用于验证本技能的原型优先边界、技术栈确认、组件证据链与交互闭环。它们是规格级验收用例，不是可直接复用的业务页面。

## 原型优先验证（硬规则）

| 检查项 | 预期 |
| --- | --- |
| 用户要求页面、后台、BI、AI 助理或截图还原 | 默认创建可交互原型，不先输出长篇方案 |
| 用户明确要求规范 / 报告 / 评审 | 才读取 `output-templates.md` 输出文本 |
| 原型存在主任务 | 至少一条“输入 → 操作 → 反馈 → 结果落点”闭环 |
| 原型工程 | 含 `evidence.json`，并通过 `validate_prototype.py` 的错误检查 |

## 路由、改进与规范沉淀验证

| 检查项 | 预期 |
| --- | --- |
| 页面同时包含基础组件、AI 对话和图表 | 分阶段加载；任一阶段不超过 `sanjin-design-expert` + 2 个伴生 |
| 现有界面只有代码差异或重复数值，没有设计契约与运行路径 | 不报告为正式设计问题 |
| 证据支持多个互斥修正 | 删除候选，不臆造产品意图 |
| 用户只要求评审 | 保持只读；最多输出 3 条通过门禁的发现 |
| 页面局部样式只出现一次 | 不写入项目 DESIGN.md |
| 更新已有 DESIGN.md | 保留已接受决策；新规则可回溯到证据账本 |

## 技术栈确认（硬规则）

| 检查项 | 预期 |
| --- | --- |
| 进入可运行页面 / 工程前询问实现栈 | Semi / Ant / TDesign |
| 用户不选择 | **默认 Semi Design** |
| 选定后禁止混用其它库 API | 通过 |

## Semi Design 证据链验证（默认栈）

### 已验证来源

- **来源级别**：`semi-mcp`
- **取证方式**：通过 MCP 查询 Layout、Nav、Table、Form、Upload、Modal、Image 等组件文档与示例
- **默认交付形态**：Vite + React + `@douyinfe/semi-ui` 工程

**验证结论**：Semi MCP 可用时，默认栈可完成高保真工程原型。实际生成新页面时仍需针对所用组件重新取证。

## 场景一：数据中台概览

### 用户任务

数据治理管理员查看今日数据任务、质量异常与待处理权限申请，并定位异常详情。

### 预期规范输出

- 顶部显示数据域、更新时间、全局日期和组织筛选，且说明影响范围。
- 概览区最多 3–5 项 KPI：任务成功率、异常任务数、数据质量告警、待审批数。
- 中部用趋势/分布解释异常；下方用明细表格承接任务列表。
- 表格固定识别列与状态，支持条件筛选、排序、分页；异常状态同时展示文本、图标和色彩。
- 不增加任务描述中未要求的权限或异常状态演示。

### 组件映射检查（按选定栈）

- **Semi（默认）**：筛选 Form/Select；明细 `Table`；确认 `Modal`——均需 Semi MCP 取证。

## 场景二：可钻取 BI 报表

### 用户任务

运营分析师从“订单完成率”概览中按区域和渠道筛选，钻取到异常订单明细并保存当前视图。

### 预期规范输出

- 首屏按“核心指标 → 趋势/比较 → 明细”排序，且每张图写明指标、维度、单位和时间范围。
- 筛选条件显示在页面上下文中；模块级筛选紧贴对应图表。
- 图表点击钻取后保留原筛选上下文，提供返回路径。
- 明细表格有固定表头、关键列优先级、排序/筛选和数据量策略。
- 不增加任务描述中未要求的无结果状态演示。

### 组件映射检查（按选定栈）

- 筛选与明细表：映射到选定栈的 Form / Table；保存视图与图表方案不推断未取证 API。

## 场景三：带引用与确认操作的 AI 数据助理

### 用户任务

分析师要求 AI“汇总近 30 天华东区域投诉上升原因，并创建一个异常监控规则”，先查看分析引用，再确认创建。

### 预期规范输出

- 结果区展示 AI 生成标识、结论、数据源、更新时间、时间范围、投诉指标口径和筛选条件。
- 支持修改条件、继续追问、重新生成和编辑结论。
- 创建规则前给出规则条件、影响范围、告警对象、执行频率和权限提示。
- 确认弹层把取消、修改和确认分开；提交成功/失败不丢失用户已输入条件。
- 只实现任务描述明确要求的 AI 结果与确认流程。

### 组件映射检查（按选定栈）

- 表单、确认弹层、明细表映射到选定栈对应组件；组合模式需在实现前补齐证据。
- **AI 对话区（按需）**：Welcome / Bubble / Sender / Sources / Actions / ThoughtChain → 对照 `companions/ant-design-x/components.md`；落地 `@ant-design/x` 或等价复刻并声明证据。

## 场景四：截图还原

### 用户任务

用户提供后台列表页截图，希望还原为可交互原型。

### 预期

- 先读取 `screenshot-to-prototype.md`，还原可见的布局与信息层级。
- 筛选、分页、详情入口等常见交互可使用合理默认值；接口、权限、隐藏 hover 行为标记待确认。
- 不补充截图和用户要求中均未出现的 loading、无结果、错误或无权限状态。
- 不默认生成体验走查或设计报告。

## 通用验收结果

| 检查项 | 结果 |
| --- | --- |
| 实现前询问技术栈；未选择默认 Semi Design | 必须执行 |
| 代码仅包含选定栈 API，禁止混库 | 必须执行 |
| 数据页面覆盖筛选、图表、表格与状态 | 通过 |
| AI 页面覆盖来源、时效、可修正与人工确认 | 通过 |
| AI 对话 UI：按需读取 `companions/ant-design-x/` | AI 产品时必须 |
| Semi 默认栈：Semi MCP 可取证 | 必须执行 |
| 生成前读取 `DESIGN.md` + `visual-quality.md`；交付前视觉清单勾选 | 必须执行 |
| 生成真实项目代码前按所需组件重新完成证据检索 | 必须执行 |
| 原型工程有 evidence.json；validate_prototype.py 无错误 | 必须执行 |
| 仅用户明确要求时输出长篇规范 / 报告 | 必须执行 |
