# 截图 / Figma 到可交互原型

当用户给出截图、设计稿或现有页面时，默认交付**可交互还原原型**，不是单独的视觉分析报告。

## 证据分层

| 层级 | 可以确认 | 实现方式 |
| --- | --- | --- |
| 可见事实 | 布局、文字、层级、颜色、密度、可见控件 | 尽量还原 |
| 强推断 | 常见的筛选、分页、展开、关闭、详情入口 | 按当前栈的通用模式实现，并标记默认假设 |
| 待确认 | 接口规则、权限、状态流转、隐藏操作、hover、失败反馈 | 用 mock / 状态演示承接，不伪造真实业务结果 |

## 识读的停止条件

低分辨率截图里的小字常常无解。**同一处文字放大两轮仍无信息增量就停**，记为待确认，继续加倍数、调对比度只是空耗。

裁切放大一次拿不准时，第二轮换手段（提高倍数或增强对比度）；两轮都读不出，说明像素信息本身不够，不是方法问题。
这类文案通常不阻塞实现：按最接近的读法先写进原型，同时列入「待确认」，交付时请用户核对。

绝不从字形轮廓猜业务词，也不从颜色、图标或位置反推含义。

## 实现步骤

1. 识别页面类型：列表、表单、详情、看板、AI 工作区或配置页。
2. 提取可见区块：全局导航、页面标题、筛选、指标、主内容、操作区、分页。
3. 识别主任务和主操作；若截图中存在多个按钮，按业务风险确定唯一 primary。
4. 根据当前选定栈取证组件 API 后实现。
5. 补齐截图不可见但原型必须有的 loading、empty/no-result、error、no-permission。
6. 用简短列表记录“已还原”和“待确认”，不要默认生成长篇走查报告。

## 禁止项

- 不从截图臆造真实接口、权限结果、数据口径或生产状态。
- 不把像素级猜测写成硬规则。
- 不用其他组件库的 API 仅为视觉相似而混库。
- 不因截图没有展示异常态而省略异常恢复路径。

## 最小交付

```markdown
原型位置：...
视觉依据：用户提供截图 / Figma
已还原：导航、筛选、表格、分页、详情入口
默认交互：筛选查询、行详情、批量确认
待确认：真实状态流转、权限、接口字段
```
